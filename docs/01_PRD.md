## 1. Обзор продукта

### 1.1 Название
**MenuScan** — SaaS-платформа цифрового меню с совместной корзиной для кафе и ресторанов.

### 1.2 Проблема
Владельцы заведений теряют деньги и время на:
- Физические меню (печать, износ, обновление)
- Ручной приём заказов официантами (ошибки, скорость)
- Отсутствие группового заказа — каждый гость заказывает отдельно или ждёт других

Гости сталкиваются с:
- Неудобными PDF-меню по QR
- Необходимостью звать официанта для каждого изменения
- Отсутствием видимости того, что заказали другие за столом

### 1.3 Решение
Платформа, которая:
1. Автоматически вытягивает меню с сайта заведения
2. Генерирует QR-коды по количеству столов
3. Показывает гостям живое меню с возможностью добавить блюда в **общую** корзину стола
4. Отправляет готовый заказ напрямую в кухонную систему или на экран повара

## 2. Целевая аудитория

### 2.1 Основные пользователи

| Сегмент | Описание | Боль |
|---|---|---|
| Владелец / управляющий | Подключает заведение, настраивает меню, получает QR | Дорогая печать, ошибки официантов |
| Гость (основной) | Сканирует QR, просматривает меню, добавляет в корзину | Долгое ожидание официанта |
| Повар / кухня | Видит заказы на экране в реальном времени | Нечитаемые или потерянные тикеты |
| Официант | Видит статусы заказов по столам | Нужно бегать и уточнять |

### 2.2 Профиль заведения
- Кафе, рестораны, фудкорты, бары
- От 4 до 100+ столов
- Наличие собственного сайта с меню **или** готовность загрузить меню вручную
- Рынок: СНГ (приоритет), далее — международный

## 3. Функциональные требования

### 3.1 Модуль владельца (Dashboard)

#### Подключение заведения
- [ ] Регистрация через email / Google OAuth
- [ ] Форма добавления заведения: название, адрес, тип кухни, логотип
- [ ] Ввод URL сайта с меню → запуск парсера
- [ ] Ручная загрузка меню через CSV / JSON как fallback
- [ ] Предпросмотр распознанного меню перед сохранением
- [ ] Редактирование блюд: название, цена, граммовка, описание, фото, категория

#### Управление QR-кодами
- [ ] Ввод количества столов
- [ ] Автоматическая генерация QR-кодов (один QR = один стол)
- [ ] Скачать все QR одним PDF (A4, по 4 на лист с номерами столов)
- [ ] Возможность переименовать стол (стол 1 → «Терраса 3»)
- [ ] Деактивация/активация стола

#### Аналитика
- [ ] Количество заказов за день / неделю / месяц
- [ ] Средний чек
- [ ] Топ блюд
- [ ] Среднее время от сканирования до оформления заказа

### 3.2 Модуль гостя (Web-приложение)

#### Меню
- [ ] Открытие по QR без установки приложения (PWA)
- [ ] Отображение категорий, блюд, цен, граммовок, состава, фото
- [ ] Поиск по меню
- [ ] Фильтры: вегетарианское, без глютена, острое и т.д. (теги на блюдах)
- [ ] Языковое переключение (RU / EN как минимум)

#### Корзина стола
- [ ] Добавление блюда в общую корзину стола
- [ ] Видимость того, кто что добавил (имя гостя, которое он вводит при входе)
- [ ] Возможность добавить комментарий к блюду («без лука»)
- [ ] Изменение количества своих позиций
- [ ] Удаление своих позиций
- [ ] Итоговая сумма по всему столу и по каждому гостю отдельно
- [ ] Кнопка «Оформить заказ» — отправляет всё на кухню

#### После оформления
- [ ] Статус заказа: принят → готовится → готов → подан
- [ ] Возможность дозаказать (новый раунд)
- [ ] Вызов официанта одной кнопкой

### 3.3 Модуль кухни (Kitchen Display System)

- [ ] Отдельный URL для кухонного экрана (без авторизации или по PIN)
- [ ] Список активных заказов по столам
- [ ] Карточка заказа: номер стола, время, список блюд с кол-вом
- [ ] Кнопки смены статуса: «Принято» → «Готовится» → «Готово»
- [ ] Звуковое уведомление при новом заказе
- [ ] Интеграция с iiko / r_keeper через webhook (v2)

## 4. Нефункциональные требования

| Параметр | Требование |
|---|---|
| Время загрузки меню | < 1.5 сек на 4G |
| WebSocket latency | < 200ms для синхронизации корзины |
| Доступность | 99.5% uptime |
| Масштабируемость | До 1000 одновременных столов на инстанс |
| Безопасность | HTTPS везде, JWT-авторизация для dashboard |
| Мобильная адаптивность | 100% — меню открывается только на телефоне |
| Парсер | Поддержка статичных HTML и JS-рендеренных страниц |

## 6. Ограничения MVP

- Парсер работает только со статичными HTML-страницами и популярными CMS (Tilda, WordPress)
- Оплата через меню — **нет** (только приём заказа)
- Интеграция с POS (iiko, r_keeper) — **нет** (только кухонный экран)
- Нативное мобильное приложение — **нет** (PWA)
- Мультиязычность — только RU в MVP
